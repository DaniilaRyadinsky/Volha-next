# Интеграционные, E2E и регрессионные тесты backend

## Запуск

Тестам нужна отдельная PostgreSQL база с именем, содержащим `test`, и применёнными миграциями `backend/migrations`. Старые тесты кеша также используют Redis. Новый сквозной стенд запускает настоящие gRPC серверы и HTTP gateway, а Redis для gateway поднимает через `miniredis`. Внешние product/auth сервисы запускать не требуется.

Пример для локальной PostgreSQL и Redis:

```bash
export POSTGRES_HOST=localhost POSTGRES_PORT=5432 POSTGRES_USER=volha_test
export POSTGRES_PASSWORD=volha_test_password POSTGRES_DB=volha_test
export TEST_POSTGRES_HOST="$POSTGRES_HOST" TEST_POSTGRES_PORT="$POSTGRES_PORT"
export TEST_POSTGRES_USER="$POSTGRES_USER" TEST_POSTGRES_PASSWORD="$POSTGRES_PASSWORD"
export TEST_POSTGRES_DB="$POSTGRES_DB" TEST_REDIS_ADDR=localhost:6379
go -C backend run ./cmd/product-service/migrator -type up
make test-integration
```

Для отдельных наборов: `make test-e2e`, `make test-regression`. Без PostgreSQL и Redis можно проверить компиляцию: `make test-integration-compile`. Команды запускаются из корня репозитория. CI поднимает PostgreSQL и Redis, применяет миграции и запускает весь набор на каждом pull request и push в `main`.

## Покрытие

| Набор | Проверяемые возможности |
| --- | --- |
| Интеграционный, gRPC + PostgreSQL | CRUD брендов, категорий, стран, материалов, цветов, продуктов, фотографий по цветам, слайдов и статей; список, пагинация, фильтры, справочники, ссылки на файлы и откат транзакции при ошибке связей. |
| Интеграционный, HTTP gateway | Административные методы создания, изменения и удаления каталога, товаров и контента; работа со статическими файлами и очистка после удаления последней ссылки. |
| Интеграционный, auth + PostgreSQL | Регистрация, вход по логину/email, аутентификация, ротация токена, выход, смена логина/пароля; полный цикл корзины, пересчёт цены и ограничение количества. |
| E2E, HTTP → gRPC → PostgreSQL | Публикация каталога администратором, загрузка изображения/PDF, просмотр посетителем, фильтрация, чтение статей и статических файлов; регистрация, профиль, корзина, смена данных и повторный вход. |
| E2E, ошибки пользователя | Нет авторизации, неверный пароль, дублирующая регистрация, неверные ID, пагинация и сортировка, отсутствие связанного товара/файла, превышение количества в корзине, доступ к административным методам. |
| Регрессионный, HTTP | Инвалидация кеша при создании/изменении/удалении товара, сохранение общего файла до удаления последней ссылки, отказ при повторном применении старого refresh-токена. |

Тестовые записи получают уникальные ID и удаляются после сценария. Файлы загружаются в отдельный временный каталог. Новые сквозные тесты не используют `t.Parallel`, поскольку gateway работает с относительными путями файлов.
